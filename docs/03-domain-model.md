# 03 — Domain model

All tables carry `tenant_id` (UUID, not null, indexed first in composite indexes), `created_at`, `created_by`,
`updated_at`, `updated_by` and an optimistic-lock `version_lock` column unless stated otherwise. IDs are UUIDs
(v7 preferred for index locality; generated by `shared.id.Ids`). Column renames for portability are in ADR-0004.
References between tenant-owned rows are composite foreign keys on `(tenant_id, id)` (ADR-0006). Table names below are the target names; the legacy source is noted
where one exists (see `06-legacy-jdms-reference.md`).

## Module: tenant

**tenant** — `id`, `code` (unique), `name`, `status` (`ACTIVE`, `SUSPENDED`), `kms_key_ref`, `default_locale`, `languages` (the languages its screens offer: `en` or `en,ar`; ADR-0023), `settings` (JSON).
The only table without `tenant_id`. Legacy: `entity_id`.

**branch** — `id`, `tenant_id`, `code` (unique per tenant; legacy `brn_cd`), `name`, `region`.

## Module: identity

**user_profile** (mirror of Keycloak users, synced on login and by admin API) — `id` (= Keycloak subject), `tenant_id`, `username`, `display_name`, `email`, `home_branch_id`, `principal_type` (`USER`, `CLIENT`), `branch_scope` (`ALL`, or `LIST` with the branches in `user_branch_scope`), `clearance` (classification level), `status` (`ACTIVE`, `DISABLED`).
Who owns which attribute (Keycloak or JDMS Next): ADR-0007. Legacy: `CM_USERS`.

**notification** — `id`, `tenant_id`, `user_id`, `type` (e.g. `VERSION_QUARANTINED`), `document_id`, `version_id`, `message`, `read_at`. In-app only (email/SMS out of scope).

**user_branch_scope** — `user_id`, `branch_id`, `tenant_id`.

**role** — `id`, `tenant_id`, `code`, `name`, `description`. Legacy: `CM_ROLEMASTER`.
**user_role** — `user_id`, `role_id`. Legacy: `CM_USERROLES`.
**delegation** — `id`, `tenant_id`, `from_user_id`, `to_user_id`, `role_id` (nullable = all delegable roles), `valid_from`, `valid_to`, `reason`, `approved_by`.

## Module: metadata

**cabinet** — `id`, `tenant_id`, `code`, `name`, `max_file_size_mb` (1–500), `quota_mb`, `default_process_key`, `status` (`ACTIVE`, `INACTIVE`).
Legacy: `DMS_FOLDER_SETTING` (keyed by `appln_name`), `DMS_FILE_SIZE_SETTING`.

**folder** — `id`, `tenant_id`, `cabinet_id`, `parent_id`, `name` (unique among siblings), `path_cache` (display only, never an identifier).
Virtual; documents reference folders but storage never depends on them. Legacy: `DMS_FOLDER_DETAIL`.

**document_type** — `id`, `tenant_id`, `cabinet_id`, `code`, `name_en`, `name_ar` (optional, ADR-0023), `category`, `channels` (JSON list), `default_classification`, `retention_policy_id`, `process_key` (Flowable process; null = no approval), `meta_change_needs_approval`, `delete_requires_approval`, `declare_record_on_approval`, `required_standard_fields` (JSON list of standard fields the type makes mandatory), `status` (`ACTIVE`, `INACTIVE`).
Codes unique per tenant (ADR-0010). Legacy: `DOC_TYPE_MASTER`, `DOC_TYPE_CREATION`, `DMS_DIRECTORY_MAINTENANCE` (mandatory fields).

**field_definition** — `id`, `tenant_id`, `document_type_id`, `field_key`, `label_en`, `label_ar` (optional), `data_type` (`TEXT`, `NUMBER`, `DATE`, `BOOLEAN`, `LOV`), `mandatory`, `max_length`, `default_value`, `lov_code`, `searchable`, `facet`, `sensitive`, `display_order`, `display_row`.
Legacy: `DOC_FIELD_DETAILS`.

**lov** / **lov_value** — `lov.code`, `lov.name`; `lov_value.code`, `label_en`, `label_ar` (optional), `display_order`, `active`.

## Module: document

**document**
- `id`, `tenant_id`, `cabinet_id`, `document_type_id`, `folder_id` (nullable)
- `title`, `status` (see spec §5), `classification`
- `branch_id`
- Standard banking keys (all indexed, all nullable): `cif`, `customer_name`, `account_no`, `collateral_code`, `contract_ref`, `transaction_ref`, `application_ref`
- `expiry_date`, `physical_location`, `physical_ref`
- `custom_fields` (JSON; validated against `field_definition`)
- `current_version_id`, `checked_out_by`, `checked_out_at`
- `record_declared_at`, `retention_policy_id`, `retention_until`, `on_legal_hold` (denormalised flag)
- `source_system` (`UI`, `INTEGRATION:<client>`, `MIGRATION`), `external_ref`, `legacy_document_id` (unique per tenant), `legacy_created_at`, `legacy_created_by` (ADR-0020)
- `deleted_at`, `deleted_by`, `status_before_delete`

Legacy: `DMS_DOCUMENT_UPLOAD` + `DMS_CUSTOM_DOCFIELD_DTS`.

**document_version** — `id`, `tenant_id`, `document_id`, `major`, `minor`, `approval_status`, `blob_key`, `sha256`, `size_bytes`, `mime_type`, `original_filename` (display only), `page_count`, `detected_mime_type` (detected by the worker from the content; `mime_type` is the uploader's claim), `version_comment`, `legacy_created_at`, `legacy_created_by` (imported versions), `storage_status`, `processing_status`, `index_status`, `encrypted_data_key` (wrapped), `key_ref`.
Unique (`document_id`, `major`, `minor`) and unique `blob_key`. A database trigger rejects changes to content columns and deletes of non-draft versions (ADR-0011).

**rendition** — `id`, `tenant_id`, `version_id`, `kind` (`PDF`, `THUMBNAIL`, `TEXT`, `PDFA`), `mime_type`, `blob_key`, `sha256`, `size_bytes`, `encrypted_data_key`, `key_ref`, `ocr` (TEXT from OCR). One per version and kind; each its own encrypted blob, written by the worker and recorded by the core (ADR-0014).

**document_link** — `from_document_id`, `to_document_id`, `link_type` (`RELATED`, `SUPERSEDES`, `ATTACHMENT_OF`). Legacy: `link_document_id`.

**retrieval_request** — `id`, `tenant_id`, `document_id` (nullable), `cif` (nullable), `type` (`DIGITAL`, `PHYSICAL`), `purpose`, `needed_by`, `status`, `requested_by`, `decided_by`, `decided_at`, `grant_until`, `issued_at`, `returned_at`. Legacy: `DMS_RETRIEVAL_REQUEST`.

## Module: access

**access_rule** — `id`, `tenant_id`, `scope_type` (`TENANT`, `CABINET`, `DOCUMENT_TYPE`, `FOLDER` (with sub-folders), `DOCUMENT`), `scope_id`, `principal_type` (`ROLE`, `USER`), `principal_id` (role code or user ID), `actions` (JSON list), `effect` (`ALLOW`, `DENY`), `branch_constraint` (`OWN`, `ALL`, `LIST` with `branch_ids` JSON), `valid_from`, `valid_to`, `approval_status` (always `APPROVED`; proposals are pending changes), `description`. ADR-0012.
Legacy: `CM_ROLEPERMISSIONS` (screen-level flags `perm_view`, `perm_save`, `perm_update`, `perm_del`, `perm_auth`, `perm_access_all`, `branch_access_all`…) and `role_id`/`doc_permission` on documents and folders.

**document_grant** — `id`, `tenant_id`, `document_id`, `user_id`, `actions`, `valid_until`, `source` (`RETRIEVAL_REQUEST`, `SHARE`), `source_id`, `revoked_at`.

## Module: workflow

Flowable owns process and task state. JDMS Next keeps its own business records:

**approval_record** — `id`, `tenant_id`, `document_id` (nullable: admin changes have none), `version_id` (nullable), `subject_type` (`DOCUMENT`, `VERSION`, `METADATA_CHANGE`, `DELETE`, `RETRIEVAL`, `ACCESS_RULE`, `ADMIN_CHANGE`, `DISPOSITION`), `subject_id` (document, version or pending change), `process_instance_id`, `task_id` (unique; null for submissions), `round_no` (1, +1 per resubmission), `stage_key`, `stage_name`, `actor_id`, `actor_name` (username at decision time), `decision` (`SUBMIT`, `APPROVE`, `REJECT`, `RETURN`, `VOTE_APPROVE`, `VOTE_REJECT`), `decision_comment`, `decided_at`. Written in the deciding transaction; never changed (ADR-0013).
Legacy: `WF_WORKFLOWHISTORY`.

**committee** — `id`, `tenant_id`, `code`, `name`, `min_quorum`, `status` (`ACTIVE`, `INACTIVE`). **committee_member** — `id`, `committee_id`, `user_id`, `designation` (unique per committee and user).
Legacy: `CM_COMMITTEE_MASTER`, `CM_COMMITTEE_USER`.

**pending_change** — `id`, `tenant_id`, `subject_type` (`CABINET`, `FOLDER`, `DOCUMENT_TYPE`, `DOCUMENT_TYPE_FIELDS`, `LOV`, `USER_ACCESS`…), `operation` (`CREATE`, `UPDATE`, `DEACTIVATE`, `DELETE`), `subject_id`, `subject_key` (natural key claimed, e.g. a new code), `base_version`, `payload` (JSON of the proposed change), `summary`, `status` (`PENDING`, `APPROVED`, `REJECTED`, `CANCELLED`, `STALE`), `proposed_by`, `proposed_at`, `decided_by`, `decided_at`, `decision_comment`, `process_instance_id` (its `single-approval` instance, ADR-0013). Used for maker-checker on metadata edits and admin changes (ADR-0009).

Process definitions (BPMN: `single-approval`, `multi-stage-approval`, `committee-approval`) and routing rules (DMN: `approval-stages`, `approval-committee`) are versioned resources in `jdms-core/src/main/resources/processes/`; Flowable keeps process and task state in its own `ACT_*` tables. Document status during approval: `PENDING_APPROVAL` → `ACTIVE` or `REJECTED`; a returned upload is `DRAFT` until resubmitted. A new major version is `PENDING` until approved (then current) or `REJECTED` (the previous version stays current). Legacy tables `WF_WORKFLOW`, `WF_ASSIGNMENT`, `WF_ALL_STAGES`, `WF_STAGES_ORDER`, `WF_BRANCHING`, `WF_COMPOUND_RULES` are migrated into process parameters and DMN tables, not copied.

## Module: records

**retention_policy** — `id`, `tenant_id`, `code`, `name`, `trigger_type` (`CREATION_DATE`, `EXPIRY_DATE`, `EVENT`), `event_type`, `period_months`, `disposition_action` (`DESTROY`, `REVIEW`), `requires_approval`.
**legal_hold** — `id`, `tenant_id`, `name`, `reason`, `status` (`ACTIVE`, `RELEASED`), `created_by`, `released_by`, `released_at`.
**legal_hold_item** — `id`, `hold_id`, `document_id`, `added_by`, `added_at`.
**record_event** — `id`, `tenant_id`, `event_type` (e.g. `ACCOUNT_CLOSED`), `account_no`, `occurred_at`: starts event-based retention for documents of that account (ADR-0017).
**disposition_batch** — `id`, `tenant_id`, `status` (`PENDING`, `EXECUTED`, `REJECTED`), `prepared_at`, `approved_by`, `approved_at`, `executed_at`. **disposition_item** — `id`, `batch_id`, `document_id`, `retention_policy_id`, `due_date`, `outcome` (`PENDING`, `DISPOSED`, `SKIPPED`, `FAILED`), `outcome_reason`.
**tombstone** — `id`, `document_id`, `tenant_id`, `document_type_id`, `document_created_at`, `disposed_at`, `disposition_batch_id`, `approved_by`, `sha256_list`.

## Module: audit

**audit_event** — `id`, `tenant_id`, `chain_seq` (position in the tenant's chain, 1, 2, …), `occurred_at`, `actor_type` (`USER`, `CLIENT`, `SYSTEM`), `actor_id`, `action`, `resource_type`, `resource_id`, `outcome` (`SUCCESS`, `DENIED`, `ERROR`), `client_ip`, `request_id`, `details` (JSON), `prev_hash`, `hash`. Append-only: the application DB user has `INSERT` and `SELECT` only. Legacy: `CM_HISTORY`.
Hash chain rules (encoding, canonical `details`, genesis value): ADR-0008. Grants and `chain_seq`: ADR-0018.

**audit_chain_head** — `tenant_id` (primary key), `last_event_id`, `last_hash`, `event_count`. One row per tenant, locked while appending.

**audit_verification** — `id`, `tenant_id`, `started_at`, `finished_at`, `trigger_type` (`SCHEDULE`, `REQUEST`), `status` (`VALID`, `BROKEN`), `events_checked`, `head_seq`, `head_hash`, `broken_seq`, `broken_event_id`, `failure` (`HASH_MISMATCH`, `LINK_BROKEN`, `SEQUENCE_GAP`, `HEAD_MISMATCH`). One row per verification run; append-only like `audit_event` (ADR-0018).

## Module: shared infrastructure tables

**job** — `id`, `tenant_id`, `type` (`SCAN`, `EXTRACT`, `RENDER`, `OCR`, `INDEX`, `REINDEX_ACL`, `DISPOSE`…), `payload` (JSON), `status` (`READY`, `RUNNING`, `DONE`, `FAILED`, `DEAD`), `attempts`, `max_attempts`, `run_after`, `locked_by`, `locked_until`, `last_error`. Polled with `FOR UPDATE SKIP LOCKED`; a claim holds a 2-minute lease (`locked_until`) that the runner renews while the job runs, so a dead runner's jobs are taken over within one lease (ADR-0021). `max_attempts` defaults to 10. `PROCESSING_RESULT` jobs carry worker results to the core (ADR-0014); `FAILED` = permanent error, `DEAD` = retries exhausted.
**event_publication** — managed by Spring Modulith (transactional outbox).
**idempotency_key** — `id`, `tenant_id`, `client_id`, `idem_key`, `request_hash`, `response_status`, `response` (JSON), `expires_at`, `created_at`; unique (`tenant_id`, `client_id`, `idem_key`); expires after 24 h.

## Search index (OpenSearch)

One index alias per tenant (`jdms-<tenant>-documents`). One entry per document (current version), plus optional per-version entries later.
Fields: `document_id`, `tenant_id`, `cabinet_id`/`cabinet_code`, `document_type_id`/`document_type_code`, `folder_id`, `status`, `classification`, `branch_id`/`branch_code`, standard banking keys, `title`, `custom_text|keyword|number|date|bool.<key>` (searchable or facet fields only, typed, never sensitive), `content` (extracted + OCR text, `en` and `ar` analysers), `created_at`, `updated_at`, `expiry_date`, `current_version`, `processing_status`, `has_text`, `on_legal_hold`.
Access is filtered at query time from `AccessPolicy.searchFilter(...)` over the indexed attributes (no per-document ACL fields, so rule and grant changes need no re-index); results are re-checked with the policy before being returned (ADR-0015).

## Blob keys

`<tenant_code>/<yyyy>/<mm>/<2 hex>/<uuid>` — no filenames, no business data in keys. The two hex characters come from SHA-256 of the blob UUID (ADR-0011).
